# ワンピ比較 — ONE PIECEカード通販価格比較

買取価格ではなく、通販の税込販売価格を比較する独立したツールです。Node.js 22以降のみで動作します。npmパッケージのインストールは不要です。

## 使い方

公開サイト: https://tksaai.github.io/OP_TCG_SHOP_COMPARE/

GitHub Actionsが**3時間ごと（日本時間 0:17・3:17・6:17・9:17・12:17・15:17・18:17・21:17）** に収集し、履歴の保存、ビルド、GitHub Pagesへの公開を行います。実行開始はGitHub側の混雑で遅れる場合があります。価格は取得に成功した商品のみ更新されます。全商品が3時間ごとに更新される保証はありません。

手動更新は `update-prices.bat` または [ActionsのRun workflow](https://github.com/tksaai/OP_TCG_SHOP_COMPARE/actions/workflows/collect.yml) で実行します。バッチには認証済みGitHub CLIが必要です。`main` へのコード・データ更新時も自動公開します。

Windowsでは `start.bat` を実行し、表示された `http://127.0.0.1:4173` を開くとローカルの保存データを閲覧できます。PCの起動は自動収集に不要です。二重収集を防ぐためローカルでのネットワーク収集は停止しています。

```sh
npm start              # 閲覧だけ。ショップへアクセスしない
npm run collect        # GitHub Actions内で収集（ローカル実行は禁止）
npm run build          # 公開用 dist を生成
npm test               # 外部サイトへのアクセスなしで検証
npm run test:coverage  # 全弾の収集状況を検証。不足があれば終了コード1
npm run history:backfill # このリポジトリに保存された旧価格JSONから実記録だけ復元
```

公開サイトは最後に正常配信したスナップショットです。閲覧・再読込はショップへの取得を発生させません。取り込み機能はそのタブ内だけの変更です。お気に入りはブラウザとサイトのURLごとに保存されるため、旧Sitesのものは移行先へ自動移行しません。

### 自動収集の状態保存

- `collector-state` ブランチにアクセス制限・巡回順・収集済み商品・価格履歴のチェックポイントを保存します。生のHTMLはGitHub Actionsのキャッシュにのみ保存します。
- 開始前に26時間の実行予約をGitHubへ保存します。終了時は失敗も含めてカウンターを保存して予約を解除します。強制停止・保存失敗では次回の取得を予約期限まで停止します（ジョブ上限45分＋24時間のアクセス制限より長い待機）。
- キャッシュが消えても制限はリセットしません。取得から3時間未満のURLは本文を失っていても再取得しません。状態ブランチが失われた場合は自動初期化せず停止します。
- 収集と公開のワークフローを直列化します。ローカルとの併用はしません。ローカルへ戻す場合は先にActionsの収集を無効化し、最新チェックポイントを引き継いでから `config/automation.json` を変更してください。
- 未収集弾があるため全弾検査の失敗は公開を妨げません。収集時に検査レポートを更新し、不足状況を画面に表示します。

## 機能と比較条件

- 「デッキ価格」にOPTCGSimの `1xOP01-001` / `4xOP01-016` 形式を貼り付け、枚数分の価格を計算。リーダーを含む全入力カードが対象です。通常版の在庫あり価格を安い順に割り当て、店舗指定と店舗ごとの参考合計にも対応します。
- 価格未取得・期限切れ・在庫不足は不足枚数として表示し、全体合計ではなく算出分の小計を示します。在庫数の判明した商品はその枚数まで使用し、枚数不明は参考計算と明示します。送料・購入制限・大会の構築制限は計算対象外です。貼り付けや計算でショップへの通信は発生しません。
- カード名・型番検索、収録シリーズ、ショップ、在庫、比較可能店舗数のフィルター。
- 在庫あり最安値、店舗間の価格差、店舗別の商品リンクと確認日時。
- お気に入り（このブラウザのローカル保存）、検索結果CSV、更新JSONの取込。
- カード詳細の店舗別価格推移（7日・30日・90日・全期間）、ショップ切替、取得履歴。
- 「ショップ・取得状況」の全弾チェック。弾・店舗ごとに未登録、未取得、一部取得、既知ページ取得、停止中を表示。
- 通常版で状態指定のない商品を自動照合。通常版でも送料は含まれません。
- パラレル、プロモ、別収録、状態指定、海外版、不明な版は店舗をまたいで自動合算しません。「すべての商品」で表示できます。安全側に分離するため、同じパラレルでも手動対応付けがない限り別商品になります。
- 36時間を超えた価格、在庫なし、在庫不明は最安値に含めません。更新に失敗した場合も元の確認日時を保持します。
- OP18・OP17と総合・新着一覧を収集します。全カードや各店の全在庫を網羅したものではありません。比較画面にも収集範囲の制限を表示します。

## 負荷対策

- 画面は保存済みJSONだけを読み込みます。検索・フィルター・再読込から収集APIは呼びません。
- 同一URLは最低3時間の永続キャッシュ。対応サイトにはETag / Last-Modified付きの条件付きリクエスト。
- ホストごとの間隔は最低10秒＋ジッター。robots.txtのCrawl-delayが長ければそちらを採用。
- robots.txtと失敗リクエストを含め、ホストごとにローリング24時間で最大20回。1回の実行は各店最大5一覧。直列収集。
- ロックファイルで同時収集を防止。実行を中断しても回数・直前アクセス時刻・休止期間は永続化。
- robots.txtは専用UA `OPCardCompare` に対応するルール（なければ `*`）を判定。robotsが404/410ならルールなしとして扱い、それ以外の不明な応答は取得停止。
- 403・429・503・接続確認画面は即停止し、24時間またはRetry-Afterの長い方まで再試行しません。その他の通信失敗は6時間停止。
- 転送は自動追跡しません。管理者が転送先を確認し設定に反映する運用です。
- 個別商品や商品画像は巡回しません。一覧ページからまとめて収集。同梱画像は既存OP_TCG_DBのローカル画像です。
- ページごとの前回データを保持し、0件や大幅減少時は上書きを拒否します。取得済みページはローテーションします。

キャッシュやカウンターを削除すると負荷制御の履歴を失います。通常運用では `.cache/` を維持してください。複数PC・複数サーバーで収集すると上限が共有されないため、収集元は1つにしてください。画像・価格・商品名の権利は各権利者に帰属します。

## ショップを追加する

1. `config/shops.json` の `shops` に一意な `id`、表示名、HTTPSの `origin`、`adapter`、`enabled`、商品一覧 `seeds` を追加。
2. `scripts/lib/sources/` にショップ専用の純粋関数を追加し、`scripts/lib/adapters.mjs` の `adapters` に登録。同じ通販基盤のHTML処理は `sources/html.mjs` を共用できますが、型番欄・価格欄・在庫根拠は店ごとに確認します。
3. 取得関数は `{title, model, price, stock, url}` の配列を返します。`stock` は `in` / `out` / `unknown`。価格は1枚の税込販売価格・整数円です。
4. ネットワーク処理はアダプターに書かず、必ず共通 `PoliteClient.page` を使用。robots、待機、上限、停止の制御が全ショップに適用されます。
5. 保存HTMLでパーサーを検証し、`node scripts/collect.mjs --shop=ID --pages=1` で小規模確認。

ショップの追加はフロント画面にも自動反映されます。`seeds` を追加すれば収録弾を増やせます。登録済みの一覧内のページ送りは自動で発見します。上限内で巡回するため、一覧数が多い場合は古い価格が発生します。欲しい収録弾を優先したい場合は不要なseedと対応する `.cache/queues.json` のURLを外してください。HTTPキャッシュとカウンターは残します。

追加した新しいseedは既存の長い巡回待ちリストより先に処理します。`seriesSeeds` に `"OP18": ["/実際のカテゴリURL"]` のように登録すると、`--series=OP18` でそのカテゴリと同じ一覧のページ送りだけを収集できます。新しく発見した続きのページも、同じ実行の残り上限内で処理します。上限で残った続きは次回に引き継ぎます。取得済みキャッシュと日次上限は通常収集と共有し、強制再取得は行いません。

### 店別の取得処理

| ショップ | 検証した違い |
| --- | --- |
| カードラッシュ | 商品名内の型番、税込販売価格、在庫枚数。通常販売とSALE商品を別のショップ商品として保持 |
| 遊々亭 | 画像altと型番欄を併用し、在庫○/×を判定。画像altが欠けても型番欄から復元 |
| フルアヘッド | EUC-JP、itemName/itemPrice、残数と注文欄。同じ商品を別カテゴリで取得しても商品IDで重複排除 |
| トレカラフテル | 型番は商品名内、モデル欄は店舗SKU。数量省略時は有効な注文ボタンを在庫の根拠にする |
| メルカード | 商品名と別欄の型番・版説明を両方保持し、残り点数を判定 |
| トレカ侍 | 括弧内の型番、注文ボタン、SOLD OUT画像オーバーレイの明示的なマーカーを判定 |
| ワンハッピー | 在庫個数、通常価格とセール価格を区別しセール価格優先。数量0なら注文文言があっても在庫なし |

店ごとの保存HTMLを `tests/fixtures/` に置き、サイトへのアクセスなしで回帰テストします。パーサー変更後は `node scripts/collect.mjs --reparse` で保存HTMLを再解析できます。HTTP通信は行わず、元の確認日時を維持します。

収録弾はカテゴリ設定から保持するため、OP18に再録された旧型番もOP18の絞り込みに出ます。TR・スペシャル・別収録は通常版と混ぜません。OP18-093「MMA」の3絵柄は店舗間のイラスト対応を確認していないため、通常版の自動最安値比較から外し「すべての商品」で個別に表示します。

### 版の手動対応付け

確認済みの商品のみ `config/identity-overrides.json` に対応付けます。キーは `ショップID:商品URLのpathname`、値は以下の形式です。同じ版・言語・状態だけに共通keyを割り当ててください。

```json
{
  "cardrush:/product/実際の商品ID": {
    "key": "OP17-093:parallel-1:ja:standard",
    "variant": "parallel",
    "label": "パラレル・イラスト照合済み"
  }
}
```

### 手動確認した販売価格の取込

`config/manual-offers.json` に配列を保存して収集を実行します。商品URLはそのショップのoriginと一致する必要があります。架空価格は使用しないでください。日時には実際の確認時刻を入れます。手動取込も36時間で最安値対象外になります。

```json
[
  {
    "shopId": "ショップID",
    "title": "正確な商品名とカード型番",
    "model": "",
    "price": 100,
    "stock": "in",
    "url": "実際の商品URL",
    "observedAt": "実際の確認日時（ISO 8601）"
  }
]
```

## ファイル構成

### 価格履歴

`public/data/history.json` にショップの商品単位で `[確認日時, 税込販売価格, 在庫状態]` を保存します。収集のたびに追記し、キャッシュ再利用・再解析では同じ確認日時の記録を重複させません。同じ値でも実際に再確認した日時が違えば記録します。販売価格が0円の欠損や取得していない過去の値は作りません。

グラフはその取得時点で確認できた店舗ごとの在庫あり最安値です。売り切れ・在庫不明も取得履歴には残しますが、グラフの最安値からは除外します。長い未取得期間や在庫切れでは線を切ります。パラレル・状態指定・未照合の版を別キーで保持し、通常版の推移へ混ぜません。価格点が1つしかない場合は点だけを表示します。

初期履歴はGitに保存していた価格JSONから復元した実記録です。記録開始以前の相場はありません。履歴はカード詳細を開いたときにだけ読み込みます。画面操作は店舗へのアクセスを発生させません。配信価格JSONをブラウザへ取り込んでも、そのファイルに含まれない過去の履歴は増えません。

### 全弾の収集テスト

`config/series-catalog.json` が監査対象です。初期対象は手元の弾マスターに存在するOP01〜18、EB01〜05、PRB01〜02、ST01〜36の61シリーズです。プロモ、ドン、将来の未登録商品は対象外なので、新弾追加時はこのマスターにも追加します。

`npm run test:coverage` はショップへの通信を行わず、設定・保存HTML・保存価格・ページ送りを照合します。結果は `public/data/coverage.json` に保存します。中間ページの抜けも検出し、総合一覧に数枚だけ含まれる弾を「その弾の取得完了」とは扱いません。既知ページ取得はあくまで登録一覧の確認できた範囲であり、店舗の全在庫・全絵柄を保証するものではありません。収集完了時にもこのレポートを更新します。

通常の `npm test` は収集ロジック自体のテストです。それが成功しても全弾取得済みとは限りません。全弾テストは不足・停止・期限切れがあれば終了コード1を返します。現時点では全弾を収集できていないため、この失敗は隠さず画面にも表示しています。

`public/` がアプリと配信用データ、`config/` がショップ・照合設定、`scripts/` が収集・ビルド・ローカル配信、`tests/` がネットワークなしの検証です。`.cache/` はローカルの作業データで、mainブランチへは追加しません。生のHTML・robots本文はActionsキャッシュに保存し、回数・処理キュー・商品情報はcollector-stateブランチへ保存します。

異常終了で `.cache/collect.lock` が残った場合は、ファイル記載のPIDのNode収集プロセスが終了していることを確認してから、このロックファイルだけを削除してください。処理の途中では削除しないでください。

## 型番ごとの収集と売り切れ参考価格

`config/shops.json` の `watchCards` に優先する型番を登録します。初期対象はEB02-017・OP09-078。店舗で確認した `cardSearch` の検索フォームを使い、検索URLが未確認の店舗は `seriesSeeds` の収録弾一覧を使用します。EB02・OP09のカテゴリを追加済みです。収集は共通のrobots・3時間キャッシュ・24時間20回の制限内で行います。

Actionsの「Collect prices and deploy」の `cards` 入力で、その回に優先する型番を最大20種類まで指定できます。入力がない定期実行はwatchCardsを使います。検索は古い確認順で巡回し、最初の2対象を先に確認してから通常巡回に戻ります。商品0件のページで別カードの確認まで打ち切らず、通信制限・robots制限・取得休止では停止します。店舗に掲載されていない商品やアクセス制限中の店舗の取得は保証できません。

売り切れの商品も価格・在庫状態・確認日時を保存します。一覧の「在庫ありのみ」は初期状態でオフです。デッキでは在庫ありの見積もりに加え、不足分を通常版の売り切れ掲載価格で補った参考試算を別表示します。状態B・パラレル・36時間を超えた価格は通常版の参考試算に混ぜません。各カードの「各店舗で探す」から手動検索もできます。

デバッグ入力が有効な手動実行だけ、対象一覧の応答を `lookup-debug` artifactに1日保存します。公開サイトには生のHTMLを配置しません。
